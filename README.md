电化学实验的溶液配制计算器 —— 稀释、称量、单位换算、缓冲液按 pH 配、标准曲线梯度稀释、
分子量解析、电化学公式。所有输入自带单位下拉，不用先把 µL 换成 L、mM 换成 mol/L。

## 模块

| 模块 | 内容 |
|---|---|
| **说一句话** | 文字描述需求，自动匹配上面任一计算；本地规则 / DeepSeek 两种解析可切换 |
| 配制 | `m = M·C·V`，四选一求解；按天平分度值给出称量相对误差 |
| 稀释 | `C₁V₁ = C₂V₂`，四选一求解；取样量 <5 µL 时提示移液误差 |
| 标准曲线 | 直接稀释 / 逐级稀释两种模式，等比或等差生成目标浓度，可含 0 空白点 |
| 液体试剂 | 浓酸等：`C = 1000·ρ·w%/M`，再算要取多少；酸入水提示 |
| 称量回算 | 实际称量偏离目标时，给「按原体积定容的真实浓度」和「该定容到多少」两个答案 |
| 缓冲液 | 按 pH 给出两种盐各称多少，带 Davies 活度校正和温度校正 |
| 分子量 | 化学式解析，支持嵌套括号与结晶水；45 条试剂库 |
| 单位换算 | 同量纲全单位列表；摩尔浓度 ⇄ 质量浓度（需摩尔质量） |
| 电化学 | 电极面积、电流密度、Randles-Ševčík、Cottrell、表面覆盖度 Γ、LOD/LOQ |
| 实验记录 | 每个结果卡下有「记一笔」，攒成一次实验的完整记录，一次性复制或导出 .txt |

## 文字输入（说一句话）

一句话描述需求，自动路由到对应计算：

```
配 20 mL 1% 壳聚糖，在 1% 乙酸中
配 50 mL 10 mM NaCl
用 K3[Fe(CN)6] 配 100 mL 5 mM
从 1 M 母液配 50 mL 10 mM，取多少
配 500 mL 0.1 M PBS pH 7.4
```

页面上可以**手动切换**两种解析：

| 模式 | 适用 | 代价 |
|---|---|---|
| **本地规则** | 规范句式，边打字边出结果 | 口语化（"20毫升"、"百分之一"）认不出 |
| **AI (DeepSeek)** | 任意句式 | 要点按钮才发送（避免按键烧额度）、需联网 |

两种模式**都只负责读懂句子，算数一律由 CORE 做**。模型输出结构化参数 JSON，灌进与本地
解析完全相同的校验与求解路径 —— 所以安全拒绝、百分比基准默认、pH 警告在两条路径上
行为一致。测试里有一条断言直接比对"本地结果 == AI 结果"，防止两条路径分叉。

共同的取舍：

- 认得出的句式，把**代入数字的公式**写出来给你核对
- **先回显"它听懂了什么"**（体积、浓度、试剂、pH、AI 的理解），误读能当场看出来
- 认不出就明说缺什么，**不编数字**

### 第三个刻意的拒绝：描述性百分数

真实句子里的百分号不都是要配的浓度：

```
含 1% (w/v) 壳聚糖、2% (v/v) 醋酸，用冰醋酸 (99.7%, 密度 1.04 g/mL)，
壳聚糖 (Mv 50,000-190,000 Da, 脱乙酰度 75-85%)
```

四个百分号只有两个是目标。判据是**位置**不是数值：括号**内**的、范围尾项、纯度/脱乙酰度
等关键词后面的，都算描述性，不参与配制，并在回显里列出被忽略的那些。目标百分数与试剂
数量对不上时**直接拒绝**，不按距离猜配对。

括号里的瓶规格 `(99.7%, 密度 1.04 g/mL)` 会被提取出来**覆盖试剂库默认值**，注释里显式
写明数值来源（"按你给的" / "按试剂库默认"）—— 显示值与回显矛盾比小误差严重得多。

### 两个刻意的拒绝

**小写 `mm` / `nm` 不当浓度。** 它们远更可能是毫米/纳米，把长度读成浓度是最危险的误读。
浓度一律要求大写 M（`nM` `µM` `mM` `M`）。

**给了摩尔质量范围就拒绝按摩尔浓度算。** 例如壳聚糖 `50,000-190,000 Da` 跨 3.8 倍，
按它算摩尔浓度，称出来的量也会差 3.8 倍 —— 这个数没有意义。会提示改用 %(w/v) 或 mg/mL。
（早期版本有个 bug：`190,000 Da` 被当成确定值硬算了，已修并加了回归测试。）

### 百分比基准的默认值

| 物质类型 | 默认基准 | 含义 |
|---|---|---|
| 固体（壳聚糖等） | **%(w/v)** | 1 g / 100 mL |
| 液体试剂（乙酸等） | **%(v/v)** | 1 mL / 100 mL |

默认值每次都会**显式提示**，要用另一种就写明 `1%(w/v)`。两者差一个密度因子，混用会错。

## 实验记录

任一模块算完，点结果下面的**「记一笔」**，攒到「实验记录」页。

**记录同步到云端（Netlify Blobs），手机和电脑共用一份历史。** 本地 localStorage 仍是
渲染来源，所以断网照常能用，联网后按 id 取并集合并 —— 记录只追加不修改，并集永远不会丢。

存储上**一条记录一个 blob**，不是整个数组一个 blob。后者在两台设备各持本地副本时，
陈旧客户端的整体覆写会悄悄吞掉另一台写入的记录。按记录分键后并发写最坏是空操作。
（这条已实测：陈旧客户端只写 t1 时，t2 依然在。）

| 功能 | 说明 |
|---|---|
| **实验分组** | 填「当前实验/批次」，之后记的都归到这组，历史按组折叠 |
| **搜索** | 按试剂、模块、实验名、结果过滤；导出只导当前筛选结果 |
| **一键重做** | 把记录回填到原模块，改个体积就重算。支持配制/稀释/称量回算/分子量/缓冲液/文字输入 |
| **AI 读历史** | AI 模式随请求带最近 8 条，可解析「上次那个 PBS 再配一次，改成 200 mL」 |

- **复制全部** —— 任何环境都能用（Artifact 链接里也行）
- **下载 .txt** —— 在 peiyetai.netlify.app 上可用；claude.ai 的 Artifact 链接会被沙箱挡掉页面
  自发起的下载，那里请用复制

导出的表格用 `|` 分隔，**不用空格对齐**。原因是实测的：

| 字符 | 相对 `0` 的宽度（本应用字体栈） |
|---|---|
| `中` `文` | **1.667** |
| `₂` `₄` | 0.977 |
| `⁻` | 0.703 |

中文字符的步进不是 ASCII 的整数倍（IBM Plex Mono 0.6em vs 中文回退字体 1.0em，
比值 5/3），Notepad 的 Consolas + 雅黑是 1.818 —— 都不是整数，所以空格补齐**在原理上
就不可能对齐**，Word 用比例字体时更不可能。只有 NSimSun、MS Gothic 这类严格半角/全角
的老式终端字体才成立。

`|` 分隔在任何字体下都成立，并且能用 Excel 的「数据 → 分列 → 按 | 分隔」直接拆成表格。
长文本换行仍遵守中文行首禁则（标点不甩到行首）。

## 和直接问 LLM 的区别

AI 只负责**读懂句子**，所有算术由 CORE 做。差别在具体场景里可以量化：

| 场景 | 本工具 | 直接问 LLM |
|---|---|---|
| 0.1 M pH 7.4 磷酸缓冲液 | Davies 校正，实测偏差约 0.19 pH | 裸 H-H，实测偏差约 0.56 pH |
| 壳聚糖 50,000–190,000 Da 按 mM 配 | 拒绝，说明差 3.8 倍没意义 | 多半取某个值直接算 |
| Randles-Ševčík | C 自动转 mol/cm³ 并写出来 | 极易用 mol/L，差 1000 倍 |
| CuSO₄·5H₂O | 解析式子得 249.68 | 可能用无水 159.6，浓度偏低 36% |
| 称 0.5 mg | 提示天平误差 20% | 不会提 |
| 1% 壳聚糖 vs 1% 乙酸 | 明说一个 w/v 一个 v/v | 通常不区分 |

也该说清楚区别薄的地方：「配 50 mL 10 mM NaCl」这种，直接问 LLM 也不会错。
价值集中在难的 case、可复现、和留痕上。

## 两个必须知道的前提

**缓冲液配比是理论值，必须用 pH 计实测微调。** 裸 Henderson-Hasselbalch 在实验室常用的离子
强度下是错的：拿标准 1× PBS 配方回测（Na₂HPO₄ 10.14 mM / KH₂PO₄ 1.76 mM，比值 5.75），

```
不校正      pH = 7.20 + log 5.75 = 7.96     实测约 7.4，差 0.56
Davies 校正 pKa₂' = 6.83 → pH = 7.59        差 0.19
```

原因是 H₂PO₄⁻ ⇌ HPO₄²⁻ 是 1→2 价跃迁，活度系数影响大。本工具默认开启 Davies 校正
（`log γ = −0.509 z² (√I/(1+√I) − 0.3I)`），离子强度由缓冲盐自身加额外背景盐算出并迭代到自洽。
但 I ≈ 0.17 M 已在 Davies 式的适用边缘，**残余误差仍有 ±0.1–0.2 pH**。

**Randles-Ševčík 式里的 C 单位是 mol/cm³，不是 mol/L**，差 1000 倍。页面按 mM 收取、内部
自动换算，并在推导行里把真正代入的 mol/cm³ 数值写出来供核对。

## 开发

```
python build.py     # src/ → index.html（单文件自包含）
node test.mjs       # 202 条断言，装配方式与 build.py 相同，跑的就是发布的代码
```

改完重新发布 —— 已接 Netlify 持续部署，**push 即发布**：

```
python build.py
node test.mjs                      # 必须全过再发
git add -A && git commit -m "..." && git push
```

推到 `main` 会自动触发 Netlify 构建，约 30 秒生效。

不要再用 `netlify deploy --prod --dir .`：它上传的是本地工作区文件，绕过 Git，
会让线上内容和仓库脱节，下次 push 又被覆盖回去。

- `src/core.js` —— 纯计算层，无 DOM 依赖，是唯一放公式的地方
- `src/parser.js` —— 自然语言解析器，**唯一来源**；core.js 里用 `/* @@PARSER@@ */`
  占位，build.py 和 test.mjs 以相同方式拼装，所以测试跑的就是发布的代码
- `src/ui.js` —— 界面层，只负责取值、格式化和渲染
- `src/shell-head.html` —— 标题、CSS、页面骨架
- `netlify/functions/ask.mjs` —— AI 解析的服务端，唯一接触 API key 的地方
- `netlify/functions/records.mjs` —— 记录的云端存储（Netlify Blobs）

改完公式务必先跑 `node test.mjs`。测试覆盖：前 12 条直接对齐原始 Excel 计算表的已知
结果，另有 Davies 校正回测、电化学公式反解自洽、全单位往返精度、CJK 文本宽度、
自然语言解析的四类路由与三类拒绝、以及 AI 桥接（含"本地结果 == AI 结果"）。

摩尔质量按 IUPAC 2021 标准原子量。
